For approval requests, check `request_approval` before parsing input or reading state. For review decisions, require `decide_proposal` from an authenticated, enabled CLI reviewer before protected work. Derive reviewer ID from the trusted actor, prevent the proposer from deciding their own proposal, and write the decision, status transition, and audit append in one immediate transaction. Recheck the expected resource version and evaluate current policy for either decision; require a fresh eligible preview and allowed policy for approval. Permit rejection when a preview is no longer eligible or policy now denies the change, because rejection grants no execution authority. The authenticated local proposal CLI invokes this service; do not expose it through an unauthenticated MCP route.

The proposal repository's pending-status list is a storage primitive, not reviewer authorization. The reviewer-facing queue service requires `review_proposals` from an authenticated CLI actor before exposing pending proposals and rechecks the current enabled identity. Queue assessments are read-only; a later decision must recheck state and policy inside its own write transaction. Keep each state change and its audit append in one caller-owned transaction before exposing the workflow through MCP or CLI.
