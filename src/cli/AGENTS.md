# CLI implementation guidance

Follow root `AGENTS.md` and `docs/cli.md`. `index.ts` owns command names, flag parsing, help, terminal guards, and safe terminal diagnostics. Importing it must not run a command or open a database. Its parser checks syntax only; a parsed path, proposal ID, or `--force` flag is never an authorization decision.

The existing migration, seed/reset, and reviewer-enrollment command functions retain their own configuration, path, migration, and prompt checks. Route to them using canonical arguments and preserve their direct npm scripts. The central router requires an interactive terminal for reset and reviewer enrollment; the older dedicated reset script has its own explicit path and `--force` boundary and no terminal check.

The router and the dedicated migration, seed/reset, and reviewer-enrollment entries use `src/cli/diagnostics.ts` for one bounded scope per handled command. Derive only the log level from the environment for diagnostic setup; each command still validates full configuration before database access. Inject a stderr sink at real entries, and keep injected test runtimes free of implicit terminal output. Pass only fixed operation names and parsed synthetic IDs; never log paths, full arguments, prompt values, credentials, actor identities, stored text, or raw errors. Logger failures must not alter command results or authentication behavior. Operational diagnostics are separate from transactional audit events.

The proposal list and review slots call authenticated handlers in `commands/proposals.ts`; audit list and verify slots call `commands/audit.ts`. Each protected invocation must challenge a human through `authenticateCliActor` on a configured, caller-owned connection, then call a capability-checked service. The audit role is chosen interactively and checked against stored credentials; no role, decision, passphrase, or approval flag supplied by CLI arguments can grant authority. Open the audit database read-only from the start and check the complete migration history and schema with read queries before prompting or reading the trace. Render stored proposal and policy text on one terminal line by removing control, direction, and invisible formatting characters. Audit output uses only validated metadata or fixed report fields, and listing does not claim chain integrity. The proposal queue display is advisory; the decision service rechecks policy and resource version inside its write transaction. Keep raw errors, SQL, local paths, configuration, and secret material out of terminal output.

When changing CLI behavior, inspect the selected route in `index.ts`, its command handler, and the service it calls before expanding to adjacent commands. Keep documented flags and database selection aligned with the router, and inspect the existing implementation before revisiting CLI work.

For reproducible CLI guidance, keep reviewer and audit commands on an interactive terminal, including `--interactive --no-tty=false` in direct Docker examples. A compiled MCP smoke client checks its own protocol path; it does not establish that human review or terminal masking worked. Use a private SQLite backup for deliberate audit-corruption examples so the active fictional demo state remains usable.

When summarizing or reviewing CLI work, name the affected command and handler rather than describing an internal service as a runnable command. Record concrete corrections and distinguish unrun interactive checks from observed results.
