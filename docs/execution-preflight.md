# Simulated execution preflight

`src/application/execution-preflight.ts` is an internal building block used by the execution service. It does not itself change a resource, create an execution, or expose an MCP or CLI route. The service supplies the configured SQLite connection, starts an immediate write transaction, calls `check` just before the simulated write, and completes the write, execution record, proposal transition, and audit append in that same transaction. A returned preview is valid only within that transaction; saving it for a later request would reintroduce a race.

The service requires an issued actor with `execute_change` before parsing input or reading SQLite. It requires an approved proposal, an independently stored approved decision by a different and currently enabled reviewer, matching decision and proposal timestamps, no execution for that proposal, and the exact expected resource version. It reconstructs the allowlisted action from validated storage, builds a fresh eligible preview, and evaluates the current policy. The current policy must allow the action and require independent review, regardless of whether its version matches the historical proposal snapshot. A newly allowed policy version may pass after full re-evaluation; an earlier policy finding alone never authorizes execution.

Missing proposals return `NOT_FOUND`. Stale resource versions and already used approvals return `CONFLICT`. Missing, rejected, inconsistent, or no longer eligible approvals and newly denied policy return `PRECONDITION_FAILED`. These expected failures use fixed domain errors without reviewer free text or stored reasons. The MCP handler maps unexpected failures to a generic internal result, without returning SQL or local paths. The execution service compares exact retry identity and payload separately before calling preflight for a new execution.
